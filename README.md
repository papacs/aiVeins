# AI 脉络（aiVeins）

给中文 AI 学习者的工程决策与反黑话手册。

它不只解释“RAG 是什么”，还回答：它解决什么、不解决什么、什么时候该用、什么时候先别用，以及最容易和哪些概念混淆。

## 为什么做这个项目

AI 术语变化快、定义边界模糊，新手很容易在碎片化文章和营销表达之间迷路。AI 脉络希望建立一套可核验、能关联、能辅助技术选择的中文内容标准。

项目坚持四条原则：

- 先讲人话，再讲机制。
- 明确适用条件，也明确边界和失败方式。
- 正式词条必须有可信来源与最后核验日期。
- 少做浅词条，多做能帮助真实选择的高混淆概念。

## 已实现

- 可搜索、可按分类筛选的术语库
- 分层词条页：30 秒解释、类比、适用/不适用、失败方式、深入阅读
- Agent vs Workflow、RAG vs 微调等高频概念对比
- 面向零基础、知识库实践者和应用开发者的学习路径
- 不追逐每日新闻的 AI 雷达
- JSON 与 `llms.txt` 机器可读出口
- WebMCP 术语搜索工具（浏览器支持时自动注册）
- 内容 Schema、关联引用与来源校验
- Issue / PR 模板、CI、行为准则与安全政策

## 本地运行

要求 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

常用检查：

```bash
npm run content:validate
npm run test
npm run lint
npm run build
```

## 内容结构

每个术语是 `content/terms/` 下的一份 Markdown 文件。Frontmatter 记录分类、状态、边界、选择条件、关联词条和可信来源；正文负责进一步解释。

```text
content/terms/       词条唯一内容源
app/                 页面与数据出口
components/          可复用界面组件
scripts/             内容校验
tests/               内容契约测试
.github/              协作模板与 CI
```

新增词条前，请阅读 [贡献指南](CONTRIBUTING.md) 并从 [词条模板](docs/TERM_TEMPLATE.md) 开始。

## 内容状态

| 状态          | 含义                                             |
| ------------- | ------------------------------------------------ |
| `researching` | 仍在收集资料或定义存在争议，不应作为确定结论引用 |
| `verified`    | 结构完整，来源与边界已核验                       |
| `outdated`    | 已确认内容过期，等待更新                         |

趋势标签（基础概念、当前热门、快速演变、存在争议）描述内容稳定性和学习优先级，不是技术排名。
