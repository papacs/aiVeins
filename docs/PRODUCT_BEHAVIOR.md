# 产品行为与验收

AI 脉络帮助读者从实际问题找到概念、判断适用边界，并完成下一步学习。首页、学习路径、对比与雷达共享 `lib/editorial.ts`，词条仍以 `content/terms/*.md` 为唯一内容源。

## 目标用户与主要流程

| 用户           | 要完成的任务                              | 入口与结果                                       |
| -------------- | ----------------------------------------- | ------------------------------------------------ |
| 零基础学习者   | 建立模型、上下文、工具与 Agent 的基本关系 | 首页直达基础路径；词条提供当前步骤和前后节链接   |
| 应用开发者     | 判断技术选择与失败处理                    | 应用路径及概念对比；提供约束、反例与最小验证建议 |
| 带着问题的读者 | 找到排查方向                              | 场景问题进入术语搜索，并链接具体对比             |

## 搜索

- 名称、别名、分类和简介使用不区分大小写的文本匹配；场景使用人工整理的问题与关键词映射。
- 场景匹配只覆盖已整理的问题，不承诺理解任意自然语言问题。
- 查询和分类共同决定结果；显示实际匹配数量与收录总数。
- `q` 和 `category` 保存到 URL，刷新、分享与浏览器返回可恢复；输入最多 80 字符。
- 空结果提供重置和贡献入口；网页与 WebMCP 搜索使用同一匹配函数。
- 使用原生输入、按钮与结果链接，Tab 定位后 Enter 打开词条；首页搜索按钮与 Enter 均可提交。

## 路径与对比

- 路径拥有稳定 ID、目标、顺序、预计阅读时间和动手检验。阅读时间是编辑估计，不是完成保证。
- 路径通过 `?path=<id>` 保留上下文，不需要账户或本地存储。当前步骤不代表已掌握或已完成。
- 不存在的路径、或不属于路径的词条，不显示路径导航；末节链接回路径练习。
- 站内链接通过 `components/site-link.tsx` 输出原生锚点，按文档跳转，不依赖客户端 RSC 路由。静态部署下保留查询参数、锚点和浏览器返回行为；路径参数在 hydration 后读取。
- 对比使用稳定锚点；标明可组合、不同层次等关系，避免暗示所有概念都是互斥选项。
- 选择、验证和反例属于编辑建议。事实依据链接到对应词条的来源与状态，不把链接的存在视为自动核验。

## 核验和编辑责任

- 列表和详情一致展示已核验、研究中、已过期；后两者不能使用“已核验”文案。
- 来源、日期、状态由词条提供，普通界面修改不更新词条核验日期。
- 贡献者在 PR 中列明核验的结论与一手依据；维护者评审关键事实、适用边界与反例后决定是否标记 verified。
- 发现结论与来源不符、协议版本改变或来源失效时，人工复查；确认过期则标记 outdated。日期久远只提示复查，不能自动证明内容错误。
- 雷达是编辑观察，不是访问统计或热度榜。尚未完成的专题明确说明，并提供相关概念作为延伸阅读。
- 自动来源可访问性检查、复查提醒与独立专题证据档案仍属后续工作。

## 验收清单

1. 首页路径、对比和雷达入口定位对应栏目；场景进入匹配结果。
2. 查询、分类、清空和空结果的数量一致；刷新和返回保留状态。
3. 路径首节无上一节，末节回到练习，中间节保留路径参数；普通词条不误显示路径。
4. 三种核验状态均正确显示；过期和研究中有解释提示。
5. 390px、768px 和桌面宽度均可访问主导航，无横向溢出；手机词条目录可展开。
6. 键盘焦点清晰，导航当前位置可识别；减少动态效果偏好下不强制平滑滚动。
7. 运行 `npm run check` 和 `npm run build:pages`；静态输出不依赖服务端读取查询参数。

自动测试覆盖内容契约、编辑引用、搜索匹配、状态文案与路径边界。响应式布局、键盘操作和页面跳转需浏览器验收。
